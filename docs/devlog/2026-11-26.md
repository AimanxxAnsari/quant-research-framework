  [design](../design/backtester.md), [learning note](../learning/backtest-accounting.md).
- `short_rates` and `splice` take a `start` date, so a backtest only needs rates for its own
  period.
- vectorbt 1.2.1 as a dev dependency for the cross-check.
- Real data, SPY/TLT/EUR/JPY 2000-2026 (6,764 days): engines agree to about 1e-14 under both
  fill rules. Weights engine 20 ms (35 ms with the look-ahead check), loop engine 5.0 s.
- Tests: 106 (48 new).

## Bugs / issues (symptom -> cause -> fix)
- Planted look-ahead strategy earned almost nothing (NAV x1.08 instead of an absurd number) ->
  it peeked one day ahead, but a decision at close t is filled at t+1 and earns t+1 -> t+2, so
  the peek lined up with a return it never held -> the planted bug now peeks at the return the
  position will actually earn. Worth remembering: the fill lag itself defeats the most naive
  look-ahead, which makes subtler versions more dangerous.
- vectorbt cross-check failed for random weights at zero cost -> vectorbt never lets cash go
  negative and shrank an order for 119% + 29% long to 71% -> tests restricted to portfolios
  that never need borrowed cash; the difference is documented in ADR-0010. I first misread
  which day's decision filled on which row and blamed the wrong cause; checking the order
  records showed the real one.
- Loading a 2024 market failed on a 2019 gap in the EUR rate history -> `short_rates` always
  built the full history -> added `start`, so only the needed period is built and checked.

# 2026-11-26 (session 3): Pillar 4 step 3, tools for judging many backtests

## Done
- `validation.sharpe`: PSR, Deflated Sharpe, minimum track record length, effective number of
  trials. `validation.pbo`: CSCV with per-block sums. `validation.splits`: walk-forward,
  purged k-fold, CPCV and its paths. `validation.selection`: pick the in-sample winner and
  collect its out-of-sample returns. `validation.multiple_testing`: haircut Sharpe
  (independent, Bonferroni, Holm, BHY) and SPA / StepM via `arch`.
- `backtest.summary`: Sortino, Calmar, hit rate, exposure, average gross leverage, and
  `cost_sweep`. [ADR-0011](../decisions/ADR-0011-overfitting-toolkit.md),
  [design](../design/validation.md), [learning note](../learning/overfitting-statistics.md).
- Known answers from the papers (read from the private copies): DSR 0.9004 / threshold 0.1132,
  0.9505 at N = 46, N = 88 with normal returns (Bailey and Lopez de Prado 2014); haircut SR 0.32
  from 0.75 (Harvey and Liu 2015). Holm and BHY equal statsmodels.
- Smoke test on 26 SPY moving-average rules (not published): all tools run in seconds.
- `arch` 9.0.0 added as a dependency. Tests: 125 (19 new).

## Bugs / issues (symptom -> cause -> fix)
- PSR test for normal returns failed -> my expected value left out the SR^2 / 2 term (the
  Sharpe estimate is noisier than 1/T even for normal returns, Lo 2002) -> test corrected; the
  code was right.
- Embargo did nothing when labels overlapped -> it started straight after the test block,
  inside the rows already purged -> it now starts after the last purged row.
- PBO on noise averaged 0.558 over 60 datasets, 2 standard errors above 0.5 -> checked with 600
  datasets: 0.512 +- 0.009, so it was chance -> the test averages 200 datasets with a 0.06
  tolerance.
- The PBO paper says 12,780 splits for S = 16 -> C(16, 8) = 12,870; a typo in the paper.
- The DSR example's numbers did not survive PDF text extraction -> used the parameters as
  remembered and checked they reproduce all three of the paper's stated results.

## Findings for step 4
- Against cash, SPA called 21 of 26 SPY timing rules significant: they mostly earn the equity
  premium. The study needs buy-and-hold as the benchmark.
- The 26 rules count as 1.7 effective trials, because being long SPY dominates their
  correlations. Measuring relative to the benchmark first may be fairer.
